What you are joining

Kituwa runs a small Kubernetes cluster on hardware it owns. A control plane schedules the work; worker nodes run the containers. Right now the worker is one machine in a room, and every spare machine that joins replaces a cloud bill with somebody's unused capacity.

Control plane

kituwa-cloud-1

Schedules workloads, serves the published sites, holds cluster state. Hosted, always on, not accepting volunteers.

Worker

trinity

Runs the builds, scrapes, renders and batch jobs. This is the kind of machine a volunteer adds: ordinary hardware, doing real work.

Open slot

your machine

A worker takes container workloads from the cluster and nothing else. No shell for anyone, no access to your files.

Install

You need a join code first — the cluster is invite-only, because a worker has to be reachable by the cluster and by nothing else. Paste it where the command asks. 

curl -fsSL https://k3s.kituwa.com/install.sh | sudo sh -s -- --code 'k3s1.…'

Any modern systemd distribution on amd64, arm64 or armv7. Needs 2 GB RAM and 8 GB free on /var.

curl -fsSL https://k3s.kituwa.com/install-macos.sh | sh -s -- --code 'k3s1.…'

k3s is Linux-only, so this creates a small Linux VM with Lima and joins the VM. Apple silicon and Intel. The VM gets no access to your home folder.

irm https://k3s.kituwa.com/install.ps1 | iex

Needs an elevated PowerShell and WSL2; the script enables systemd inside WSL and runs the same Linux installer there. Your Windows files stay out of the cluster. Paste the join code when asked.

Read it before you run it. Both scripts are plain shell and PowerShell, with no bundled binaries. Read them first: curl -fsSL https://k3s.kituwa.com/install.sh | less.

Leaving is one command: curl -fsSL https://k3s.kituwa.com/install.sh | sudo sh -s -- --uninstall --remove-tailscale

What the installer actually does

  1. Checks the machine

    Linux with systemd, supported architecture, at least 2 GB of RAM and 8 GB free on /var. It refuses rather than half-installs.

  2. Joins the tailnet

    Installs Tailscale from its official script and joins with the key inside your join code, tagged tag:k3s. That is the only network path the cluster uses.

  3. Writes two small files

    /etc/rancher/k3s/config.yaml and a 0600 token file. Nothing in your home directory.

  4. Runs the official k3s installer

    Agent mode only, version pinned to the cluster, binary checked against its published sha256.

  5. Waits for the node

    Confirms k3s-agent is active and reports the node name. If it fails, it prints the log and stops.

The node is then a normal Kubernetes worker: the scheduler places pods on it, and it runs them in containers until you remove it.

What it will not do

  • No access to your files. The node runs containers with their own filesystems. Your home directory is not mounted.
  • No shell for anyone. Cluster access is limited to the control plane; a worker does not hand out logins.
  • No mining, no scans, no proxies. This does not join a mining pool, probe networks or relay traffic.
  • No crypto keys, no wallets, no card data. None of that runs on worker nodes.
  • No lock-in. One uninstall command removes the agent, its config and, if you ask, the tailnet login.
  • No hidden binaries. Everything is a readable script from a public MIT repository.

Contributor tiers

Tiers describe the machine you bring, not a payment plan. Today they are credit and a line on this page — nothing more. If the work earns money one day, rewarding contributors is something worth doing, but it is a hope, not a promise, and nothing here should be read as an investment.

TierMachineWhat it is good for
Node2–4 cores, 4–8 GB RAMSmall services, scheduled jobs, builds
Workhorse8–12 cores, 16–32 GB RAMRenders, video, scraping at scale
Cluster16+ cores, 32 GB+ RAM, GPU optionalBatch pipelines and model work

A tier changes nothing about how the cluster treats the node: workloads are scheduled by capacity and labels, never by tier name.

Get a join code

Joining is by invitation. A join code is a single line that carries the cluster address, a bootstrap token limited to joining a worker, and a tailnet key tagged for cluster use. Codes are issued per machine and can be revoked at any time — revoking one removes that machine's access without touching anyone else.

Trust, plainly

You can audit everything

The installer, the macOS wrapper, the Windows wrapper and the operator tool that mints codes are all in one public repository. No compiled artifact, no obfuscation, no third-party download besides Tailscale and the official k3s installer.

github.com/CrystalRockMarket/k3s-join

What the join code contains

A server address, a bootstrap token that can only be used to add a worker, and a tailnet auth key scoped to the cluster tag. It cannot read cluster secrets, run commands as you, or reach your network.

A worker is a machine the cluster can schedule pods on. If that ever feels wrong, --uninstall ends it, and the node drains its pods before it goes.
