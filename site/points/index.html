How the cluster decides to use your machine

This is old-school SETI in a modern wrapper. Your machine is a worker in a Kubernetes cluster — but it is not a server. It only takes work when you are not using it.

  1. You are working — it is not

    When the machine is in use, the node is marked busy and the scheduler puts no new work on it. Nothing is killed mid-task; it simply stops being offered work.

  2. The screensaver moment

    Walk away and the node becomes available again. Think of it as “if the screensaver is on, your machine is a worker” — we do not need the screensaver itself, just the machine sitting idle.

  3. Work runs in containers

    Jobs arrive as ordinary container workloads: a render, a scrape, a build. They get their own filesystem and no access to your files.

  4. It earns, visibly

    Every second of CPU it spends on cluster work is a point on this page, under your machine's name.

Why idle matters. A laptop that is being typed on should not spin up a render. The cluster treats “in use” as sacred: idle is the only state in which a volunteer node accepts new work, so joining never costs you the machine you are actually using.

Points are proportional

One point is 100 CPU-seconds, credited to the machine that spent it. Give 10% of the work and you earn 10% of the points; give ten times the work and you earn ten times the points. No bonus is based on who you are, when you joined, or how many machines you run — only on measured work, and a volunteer's idle-only rule changes when it counts, never how much.

New machines start at zero and earn from their first measured sample.
